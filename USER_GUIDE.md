# 📘 Руководство пользователя «Код Мастер»

Данное руководство поможет вам начать работу с приложением **Код Мастер** и использовать все его возможности.

---

## 📥 Установка

### Windows (портативная версия)

1. Перейдите на страницу [Releases](https://github.com/GrafKD/code_master/releases).
2. Скачайте последний релиз. Это может быть:
   - **Стабильный релиз** — `Release v1.x.x`.
   - **Тестовая сборка** — `Nightly build ...` (pre-release).
3. Распакуйте архив.
4. Запустите `CodeMaster.exe` двойным кликом.

> ⚠️ Приложение портативное. Оно не требует установки, прав администратора и не оставляет записей в реестре. Настройки сохраняются в файл `config.json` в пользовательской папке данных (`~/Library/Application Support/CodeMaster` на macOS, `%LOCALAPPDATA%\CodeMaster` на Windows, `~/.local/share/CodeMaster` на Linux).

### Сборка из исходников

Если вы хотите запустить приложение из Python-кода:

```bash
git clone https://github.com/GrafKD/code_master.git
cd code_master
pip install -r requirements.txt
python main.py
```

Требования: Python 3.10+, PySide6, pyserial.

### Драйверы интерфейсов

Приложение не устанавливает системные USB-драйверы автоматически.

- **UART/USB-UART:** установите драйвер своего адаптера CH340/CH341, CP210x или FTDI. После установки порт появится как COM-порт (Windows) или `/dev/ttyUSB*`/`/dev/ttyACM*` (Linux).
- **USB CDC CodeMaster:** Windows 10/11, macOS и Linux обычно используют встроенный CDC-драйвер. На Linux пользователю могут понадобиться udev-права на `/dev/ttyACM*`.
- **STM32 ROM DFU (`0483:DF11`):** в Windows нужен WinUSB/libusb-драйвер (например, через Zadig или STM32CubeProgrammer). В Linux нужны libusb и udev-правило.
- **ST-Link:** установите ST-Link USB-драйвер/ПО ST или настройте WinUSB/libusb для используемого pyOCD backend. В Linux добавьте udev-правила.
- **J-Link:** установите SEGGER J-Link Software and Documentation Pack, включая J-Link DLL и USB-драйвер. Одного `pylink-square` недостаточно.

После установки драйвера переподключите устройство и нажмите **Обновить список портов** или выберите способ **Авто**.

## 🔌 Первое подключение

После запуска приложения вы увидите главное окно. Для работы с STM32 или CAN-шиной нужно подключиться к COM-порту.

### Порядок действий

1. Нажмите кнопку **Настроить** (или `Ctrl+O` / `Ctrl+M` для быстрого открытия окна).
2. В диалоге выбора COM-порта:
   - Выберите порт из списка (например, `COM3` на Windows или `/dev/ttyUSB0` на Linux).
   - Укажите скорость (обычно `115200`).
   - При необходимости включите **Режим эмуляции** — приложение создаст виртуальный порт для тестирования.
   - Включите **Автопереподключение**, если хотите, чтобы приложение само восстанавливало связь при разрыве.
3. Нажмите **Подключить**.

Индикатор порта внизу окна станет зелёным, если подключение успешно.

## 🔥 Прошивка STM32

Приложение прошивает микроконтроллеры STM32 через встроенный UART bootloader.

### Пошаговая инструкция

1. Подключите STM32 к компьютеру через UART-USB адаптер и переведите его в режим bootloader (замкните BOOT0 на VCC, нажмите RESET).
2. В главном окне нажмите **Обновить** (или `Ctrl+O`).
3. Выберите файл прошивки `.bin` или `.hex`.
4. Нажмите **Открыть** — начнётся процесс прошивки.
5. Наблюдайте за прогресс-баром. После успешного завершения появится сообщение.
6. Переведите микроконтроллер в рабочий режим (отключите BOOT0 от VCC, нажмите RESET).

### Если прошивка не идёт

- Убедитесь, что порт открыт и устройство отвечает.
- Проверьте правильность скорости (обычно 115200).
- Попробуйте переподключить питание STM32 и повторить.
- Посмотрите логи — кнопка **📄 Логи** в главном окне.

## ⚡ CAN Тригеры

Тригеры позволяют автоматически отвечать на определённые CAN-кадры.

### Как настроить

1. Откройте окно настроек и перейдите на вкладку **CAN Тригер**.
2. В одном из блоков (их 10) заполните:
   - **ID** — CAN-идентификатор, на который реагирует триггер.
   - **D0–D7** — данные для фильтрации (можно оставить пустым, тогда сработает по любым данным).
   - **Активен** — включить триггер.
   - **ID отв.** — идентификатор ответного кадра.
   - **D0–D7 отв.** — данные ответного кадра.
   - **Задержка мс** — пауза перед отправкой ответа (0 — мгновенно).
3. Нажмите **Применить**.
4. Для проверки нажмите **Тест** — ответный кадр будет отправлен вручную.

> 💡 Каждый триггер имеет счётчик срабатываний. Он отображается рядом с чекбоксом «Активен».

> 💡 Триггер с несколькими кадрами ответа записывается в устройство группой связанных записей и исполняется самим МК — приложение для его работы не нужно. Исключение — суммарная задержка расписания больше ~65 секунд: такой триггер помечается **«исполняется приложением»** и работает только пока открыта программа. Выключенный (галка снята) триггер хранится в устройстве неактивным и не срабатывает нигде.

> 💡 В полях **Data приёма** можно вводить символ **X** — это байт-заглушка: позиция с «X» не участвует в сравнении, триггер сработает при совпадении остальных байт.

> 💡 В строке **Приём** есть две опции:
> - **Слушать отправляемое** — включено: триггер реагирует и на кадры, отправленные самим МК (например, ответы других триггеров); выключено: только на кадры с шины.
> - **Кол-во сработок до смены DATA** — при включённой галочке триггер отрабатывает указанное число раз (1–9999) на кадрах с одинаковым содержимым, затем молчит; как только Data меняется, счёт начинается заново.

### Автоматическая запись DATA в Кэш

Режим кэша позволяет триггеру отвечать последними принятыми данными. У каждой строки кэша — свой источник (канал, ID, DLC и побайтовый диапазон «От»–«До») и своя отправка (канал, паузы, количество). Строк добавляется кнопкой **+** — один входящий кадр может пополнить сразу несколько строк.

- В полях **От**/**До** также работает **X**: байт игнорируется при сравнении, а в ответном кадре на его месте уходит `00`.
- При срабатывании триггера устройство отправляет закэшированные кадры всех строк с их таймингами и количеством — как многофреймовый ответ.
- Режим кэша исполняется самим МК и продолжает работать без приложения.
- У каждой строки есть те же опции, что у приёма: **Слушать отправляемое** (кэшировать ли кадры, отправленные самим МК) и **Кол-во сработок до смены DATA** (остановить захват после N кадров с одинаковой Data до её смены — в кэше остаётся последнее значение).

## 📊 CAN Мониторинг

Мониторинг позволяет видеть весь CAN-трафик в реальном времени.

### Как запустить

1. Откройте вкладку **CAN Мониторинг** в окне настроек.
2. Для каждого канала (CAN1 / CAN2) нажмите **Старт**.
3. Входящие кадры будут появляться в таблице с отметкой времени, ID, данными и DLC.

### Полезные функции

- **Фильтр ID** — показывать только кадры с нужным идентификатором.
- **Приостановить** — временно остановить обновление таблицы.
- **Очистить** — очистить таблицу.
- **Отправить** — вручную отправить кадр с указанным ID и данными.
- **Циклически** — автоматически повторять отправку кадра с заданным интервалом.
- **Запись в CSV** — сохранить весь принятый трафик в CSV-файл.
- **Контекстное меню** — клик правой кнопкой по строке позволяет скопировать ID или данные, а также создать триггер на основе кадра.

## 🔄 CAN Шлюз

Шлюз позволяет перенаправлять кадры между каналами и заменять их содержимое.

### Настройка

1. Откройте вкладку **CAN Шлюз**.
2. В разделе **Игнорируемые ID** введите ID, которые не нужно пересылать.
3. В разделе **Правила замены** добавьте пары:
   - **Входной ID** — кадр, который пришёл.
   - **Выходной ID** — кадр, который уйдёт вместо него.
4. Нажмите **Применить**, затем **Старт**.

> ⚠️ Для работы шлюза оба канала должны быть активны.

## 🩺 Диагностика bootloader

Для быстрой проверки связи с STM32 bootloader:

1. Подключите устройство к COM-порту.
2. В главном окне нажмите **Диагностика**.
3. Приложение запросит версию bootloader и ID устройства.
4. Результат отобразится в окне сообщения.

Если устройство не отвечает, проверьте:
- правильность выбора порта;
- что устройство находится в режиме bootloader;
- наличие связи по UART.

## 🧾 Лог МК

Помимо лога приложения на ПК, само устройство ведёт собственный журнал
событий во Flash — он переживает отключение питания и не зависит от
того, был ли подключён ПК в момент события. Полезен для случаев, когда
связь с устройством пропадает без видимой причины (например, требуется
физически отключить и подключить провод CAN, чтобы связь восстановилась)
— журнал показывает, что происходило на МК в этот момент.

1. Откройте вкладку **🧾 Лог МК** в настройках устройства.
2. Нажмите **Считать лог** — приложение вычитает журнал с устройства
   постранично (может занять пару секунд при большом количестве записей).
3. В таблице появятся записи: время (аптайм МК с последнего включения),
   тип события (старт МК, ошибка/bus-off CAN, переполнение приёма, USB
   reset/disconnect и т.д.), канал и детали.
4. Кнопка **Экспорт в файл** сохраняет текущую таблицу в текстовый файл —
   удобно приложить к обращению в поддержку.

Устройство никогда не стирает журнал по команде с ПК и не приостанавливает
запись новых событий во время чтения — кнопка «Считать лог» можно нажимать
многократно, в том числе на живой шине. Старые прошивки эту функцию не
поддерживают — приложение сообщит об этом при попытке чтения.

## � Библиотека конфигураций

Библиотека позволяет хранить и быстро переключать профили настроек (триггеры и правила гибкой логики) в файлах `.cmm`.

1. Откройте вкладку **Библиотека**.
2. Слева выберите категорию: производитель, «Универсальные» или «Пользовательские».
3. Выберите конфигурацию и нажмите **Предпросмотр**, чтобы увидеть содержимое.
4. Нажмите **Загрузить**, чтобы применить профиль к текущим триггерам и правилам.
5. Кнопка **Сохранить текущие настройки как…** экспортирует активные триггеры/правила в новый `.cmm` файл.
6. Используйте **Импорт .cmm** и **Экспорт .cmm** для обмена профилями.

Профили хранятся в папке `library/` рядом с приложением. Демо-профили уже включены в поставку.

## � Трэйс CAN-шины

Вкладка **🔬 Трэйс** записывает CAN-трафик в две хронологические таблицы — отдельно для CAN1 и CAN2 — и позволяет воспроизвести записанные кадры обратно в шину.

1. Откройте вкладку **Трэйс**.
2. Нажмите **Начать анализ** — принимаемые кадры добавляются в таблицу своего канала.
3. Нажмите **Завершить анализ**, чтобы остановить запись.
4. Для каждого кадра в таблице видны: время, ID, DLC, данные, период следования, ASCII-представление, пояснение (по загруженному DBC) и направление (RX/TX).
5. **Экспорт CSV** и **Экспорт .trace** сохраняют записанный трафик в файл.
6. **Загрузить лог…** загружает `.trace` или CSV обратно в таблицы.
7. Кнопки под каждой таблицей воспроизводят кадры в шину: **Отправить** (все строки или только выделенные), **Replay ⏱** (с исходными таймингами из лога), **По кадрам** (по одному кадру на нажатие), **Стоп** — прервать воспроизведение.

## 📄 DBC-файлы (OpenDBC)

В поставку включена локальная копия базы OpenDBC (comma.ai, лицензия MIT) — описания CAN-сообщений для многих автомобилей.

1. Откройте вкладку **📚 Библиотека**.
2. Нажмите **Загрузить DBC из OpenDBC**.
3. В диалоге слева выберите марку — справа появится список сообщений выбранного DBC (ID, DLC, название, описание).
4. Двойной клик по сообщению создаёт из него триггер на вкладке **⚡ Триггеры**.

Файлы OpenDBC лежат в `library/dbc/opendbc/` и доступны при следующем запуске.

## �🔧 Решение проблем

### Порт не виден в списке

- Убедитесь, что адаптер подключён к компьютеру.
- Проверьте драйверы USB-UART адаптера (CH340, CP2102, FTDI и т.д.).
- Перезапустите приложение.

### Устройство не отвечает при прошивке

- Проверьте, что STM32 находится в режиме bootloader (BOOT0 → VCC, RESET).
- Убедитесь, что скорость порта совпадает с настройками bootloader (обычно 115200).
- Проверьте линии RX/TX — они должны быть перекрещены (RX платы → TX адаптера, TX платы → RX адаптера).
- Проверьте общий GND.

### Ошибка синхронизации bootloader

- Убедитесь, что устройство действительно STM32 с поддержкой UART bootloader.
- Проверьте, что bootloader разблокирован (если включена защита от чтения, прошивка может не идти).
- Попробуйте снизать скорость до 9600 и повторить.

### Приложение не запускается

- Для Windows: убедитесь, что у вас Windows 10 или 11 (64-бит).
- Для разработчиков: проверьте, что установлены все зависимости из `requirements.txt`.
- При запуске из Python может потребоваться виртуальное окружение:

```bash
python -m venv .venv
source .venv/bin/activate  # Linux/macOS
# .venv\Scripts\activate   # Windows
pip install -r requirements.txt
python main.py
```

### CAN-кадры не приходят

- Убедитесь, что CAN-модуль подключён к выбранному COM-порту.
- Проверьте скорость CAN-моста и скорость COM-порта.
- Попробуйте запустить мониторинг на обоих каналах.
